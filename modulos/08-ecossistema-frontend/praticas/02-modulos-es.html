Prática 02 – Módulos ES Nativos no Navegador

Os navegadores modernos suportam ES Modules nativamente! Não é preciso bundler para experimentar: basta type="module" no script. Esta página usa módulos inline para demonstrar os conceitos.

1. import() Dinâmico

💡 O import() dinâmico permite carregar módulos sob demanda (lazy loading). É assíncrono e retorna uma Promise.
// Carregamento lazy – só executa quando necessário const modulo = await import('./utils.js') modulo.minhaFuncao() // Ou desestruturando const { calcular } = await import('./matematica.js')
Módulo não carregado ainda.

2. Módulo de Utilidades (simulado)

💡 Em um projeto real, cada função estaria em um arquivo .js separado. Aqui simulamos com módulos inline para demonstração.
// matematica.js export const PI = 3.14159 export function circunferencia(r) \{ return 2 * PI * r \} export function area(r) \{ return PI * r ** 2 \}
Informe um raio e clique em calcular.

3. Módulo de Estado (Store)

💡 Módulos são singletons – a mesma instância é compartilhada por todos os importadores. Isso torna módulos ótimos para gerenciar estado.
// store.js – módulo singleton let _estado = \{ contador: 0, mensagens: [] \} export function getEstado() \{ return \{ ..._estado \} // retorna cópia \} export function incrementar() \{ _estado.contador++ \} export function adicionarMsg(msg) \{ _estado.mensagens.push(msg) \}
Clique nos botões para alterar o estado.

4. Tree-shaking

💡 Tree-shaking remove código exportado mas nunca importado. O bundler (Vite/Rollup) analisa os imports e elimina o código morto.
// utils.js – tem 5 funções exportadas export function funcaoA() \{ ... \} // ← usada export function funcaoB() \{ ... \} // ← usada export function funcaoC() \{ ... \} // ← NÃO usada export function funcaoD() \{ ... \} // ← NÃO usada export function funcaoE() \{ ... \} // ← NÃO usada // app.js – importa apenas A e B import \{ funcaoA, funcaoB \} from './utils.js' // No build: C, D, E são removidas! // Resultado: bundle 60% menor
Clique para simular o tree-shaking.

5. ES Modules vs CommonJS

// ✅ ESM – use sempre em projetos modernos import axios from 'axios' import \{ useState \} from 'react' export const PI = 3.14 export default function App() \{ ... \} // ❌ CJS – apenas em código Node.js legado const axios = require('axios') module.exports = \{ PI: 3.14 \} // Diferenças chave: // ESM: estático, tree-shakeable, async (top-level await) // CJS: dinâmico, síncrono, Node.js nativo (legado)
Clique para ver as diferenças.

6. Estrutura de um Projeto Vite

💡 Depois de criar um projeto com npm create vite@latest, esta é a estrutura típica que você encontrará.
meu-projeto/ ├── public/ # estáticos não processados │ └── favicon.svg ├── src/ # código fonte │ ├── components/ # componentes reutilizáveis │ ├── pages/ # páginas/views │ ├── assets/ # imagens, fontes │ ├── App.jsx # componente raiz │ ├── main.jsx # ponto de entrada │ └── index.css ├── index.html # template HTML (entrada Vite) ├── package.json ├── vite.config.js # configuração └── .gitignore
Comandos principais:
npm run dev – servidor de desenvolvimento
npm run build – gera /dist otimizado
npm run preview – previsualizar o build
